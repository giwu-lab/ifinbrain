业务重塑前后对比

同样的一个财务月，流程改造前与改造后的差别

改造前 · 人工台账
录入方式
逐张打开文件手工敲，十几个字段全靠眼睛
查重手段
翻文件夹 + 查 Excel，低命中率且易误判
多格式处理
PDF/XML/OFD 各算一张，台账张数对不上业务票数
审批联动
两套系统互不相通，结果靠人工回填
归档方式
命名规范靠员工自觉，脱轨文件永远进不了账
发票识别服务
改配置要改代码，换供应商即重装环境
导出台账
一次性全量加载，数据量一大就卡死或超时
›
改造后 · iFinBrain
录入方式
上传即 OCR 识别，字段全部可编辑，机器打字、人来判断
查重手段
批次内 + 全库双层查重，命中即阻断提交，另有一键去重清理
多格式处理
一个发票号一行，PDF/XML/OFD 归一呈现
审批联动
一张报销单一次审批，状态自动回写未报销/审批中/已报销/已驳回
归档方式
自动重命名并按报销单号归集，归档结构等同业务结构
发票识别服务
页面配置热生效，API Key 加密存储永不回显
导出台账
游标分批流式导出，内存峰值与数据总量无关

错误可诊断，而不是只给一句「失败了」

识别失败被拆成三类，各自给出修复入口：服务未配置跳配置页；API Key 已失效（主密钥轮换导致无法解密）引导重填；调用失败引导检查地址与在线状态。

存储可热切换

本地磁盘 / S3 兼容（MinIO、COS、OSS、OBS）页面配置后立即生效，新文件走新存储，历史文件保持不动，无需重启。

权限到操作级

查看、上传、删除、提交报销各自独立权限点，前后端双重校验，按角色（admin / operator / viewer）分配。

发票管理的终点，不是「录入完成」，而是 可入账、可归档、可分析。
